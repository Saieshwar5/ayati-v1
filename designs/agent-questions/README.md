# Durable question controls and local evidence

These controls reuse Relay's compact message references, native review drawer,
labels, fields and theme tokens. The agent supplies declarative question data;
Ayati owns rendering, response routing and authority. No generated interface code
or new design dependency is introduced.

- [Desktop typed form](question-form-desktop.png)
- [Phone typed form](question-form-mobile.png)
- [Saved answer in dark mode](question-saved-dark.png)
- [Closed choice on a narrow phone](question-closed-choice-mobile.png)

Captures use disposable simulation identities and fictional work. The journey
runs pinned Goose with a scripted local model, PostgreSQL and authenticated MCP
records. It demonstrates a saved question, worker release, restart, typed answer,
fresh task continuation and independent exact business approval before one write.
Multiple choice, private managed agents, decline/Stop, source revocation, keyboard
focus and mobile/dark layouts are also checked. A separate case exercises the
controller-local broker using an isolated compatibility worker.

See [the runtime/API contract](../../runtime/agent-questions.md) for schema 23,
response semantics and adapter limits. These are local fixture results; existing
SQLite/private-runtime adapters, hosted authentication, commercial model quality
and cloud capacity are separate acceptance work. No customer data, paid inference
or cloud deployment is involved.

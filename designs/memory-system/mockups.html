Design proposal · not built

One memory system for the whole product

Agents learn while they work. What they learn is kept at the level where it is useful and safe: the whole workspace, one agent's job, one channel, or one person. Every level uses the same engine. The rooms Cuckoo already has decide what an agent may read and write in each request.

The map

Four shelves of memory, and the real messages beside them

Think of a company. Some things everyone knows. Some things one employee knows about their own job. Some things belong to one team's room. Some things are between an employee and one colleague. The memory has the same four levels.

What goes where

What each shelf remembers

The engine is the same. The content is different, because each shelf answers a different question.

Workspace memory

"What is true about this business, whoever asks?"

  • Acme Traders pays 45 days after invoice.
  • Ravi approves any discount over 10%.
  • The price list is the "Prices 2026" sheet, updated on Mondays.
  • "The Friday report" means the weekly stock summary.

Never: private matters, secrets, live numbers such as stock or balances, rules for agents.

Job shelf ONE AGENT

"What have I learned about doing my own job?"

  • The sheet update fails over 500 rows; send batches.
  • Quote templates are in the Sales folder.
  • I post the stock report in #ops every Monday.
  • Reminders sent before 11 am get answered the same day.

Never: anything about one person. Rules stay in Lessons, approved by a person.

Room shelf ONE AGENT · ONE CHANNEL

"What has this room settled?"

  • #sales decided on 3 Nov to quote in rupees only.
  • This room wants numbers as a table.
  • The Diwali offer ended on 14 Nov.
  • Arjun handles returns questions here.

Never: used outside this room.

Person shelf ONE AGENT · ONE PERSON

"How do I work well with this person?"

  • Meera wants short answers, in Hindi when she writes in Hindi.
  • Meera handles the Pune accounts.
  • She is waiting for the Northwind credit note.
  • She asks for the overdue list every Monday.

Never: used for anyone else or in a channel. She can read and remove it.

Writing

Where a new note is filed

The agent keeps a note with one tool, remember, and says who it is for. The server sets the limit. The agent can make the audience smaller, never wider.

The agent choosesIt asks itselfSaved at once whenOtherwise
hereIs this about this person or this room?Always. It goes on the shelf of the conversation it is working in.—
my jobWill I need this in every conversation?It was learned in a public channel or from the agent's own tool result.An owner approves it, under Lessons.

Anything read from email, the web or a connected app waits for a person before it can sit above "here". A schedule or trigger running by itself can only suggest.

Reading · the one rule

A memory is used only where everyone who reads the answer could have seen where it was learned

The server works this out from the running request. The agent cannot name another person or room, so it cannot ask for the wrong shelf.

Finding

How an agent decides where to look

Mostly it does not have to decide. Three things do the work.

1. Given with every request

No search needed. The size is fixed, however large the memory grows.

  • Workspace essentials 2,000 characters
  • The agent's job essentials 1,500
  • Top notes of this room or person 1,500
  • Up to 3 topic summaries that match the request 3,000

2. One search, every allowed shelf

search_memory looks through all the shelves this request may read. Each line says where it comes from, so the agent never has to pick the right shelf.

search_memory "Acme payment" in Meera's chat
[workspace]Acme Traders pays 45 days after invoice.
[this conversation]Meera wants Acme reminders sent to Priya S.
[my job]Acme's invoices need the PO number in the subject.

3. A short ladder in its instructions

The agent needsIt looks in
A lasting fact: who, how, what was decidedWhat it was given, then search_memory
What was said, when, by whom, exact wordssearch_conversation_history
The text of a document or policyThe Library
A live number: stock, balance, order statusThe connected app. Never memory.
Nothing foundIt says so and asks. It never guesses.

When notes disagree, the closer one wins: person or room, then job, then workspace, unless an admin pinned the wider note. When a newer message disagrees with a note, the message wins and the agent ends the note.

The work

What changes and what is new

Existing things that change

  • History search: today exact words in at most 256 messages; becomes ranked search over the whole conversation, with dates and author.
  • What an agent is given: a Memory block is added, and the ladder in its instructions.
  • Activity: memory and history lines on a request.
  • Agent page and Conversation context: the additions above.
  • Lessons review: also approves notes filed wider.
  • Removing a person, narrowing a channel: also deletes or fences their shelves.

Stays as it is: assistant memory, notes and lessons, the room brief, skills, the Library.

New systems to build

  • The memory store: one set of tables for all four shelves.
  • The scope rule: one function that decides, from the running request, which shelves may be read and written.
  • Three agent tools: remember, end a note, search memory.
  • The record of memory use, which feeds Activity, strength and "Looked for, not found".
  • The nightly tidy-up: merge, settle, summarise, fade, archive, delete.
  • The approval queue for wider filing and outside sources.
  • Settings › Memory and the two agent-page panels.

Build order

Six steps, each useful alone

Strict from the first day: the boundaries and the record of every action. Simple at first, smarter with data: word search before meaning search, notes before summaries, fixed strength before fading.

  1. Better history searchThe tools exist and the scope is already safe. It also adds the record every later step needs.People see: the agent finds what they said months ago.
  2. Room and person shelvesThe store, the scope rule, remember and search, the Undo line, About you.People see: the agent remembers how they like answers.
  3. The job shelfNotes for every conversation, with owner approval for anything from a private place.Owners see: what their agent learned about its job.
  4. Workspace memoryThe widest audience, so it comes after the engine is proven on small ones.Admins see: Settings › Memory.
  5. The memory looks after itselfStrength, fading, merging, summaries, the Changes list with undo, search by meaning.Admins see: Fading, Archive, Changes.
  6. Measuring, and the later partsLooked for not found, corrections after use, searching a person's channels from their direct chat.Everyone sees: fewer repeated corrections.
